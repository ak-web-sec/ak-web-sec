ExampleCorp SA — External Web Application Pentest

Date: July 2026 | Scope: examplecorp.co.za, api.examplecorp.co.za | Classification: Confidential

Executive Summary

AKWEBSEC conducted a manual penetration test against ExampleCorp SA's external web applications over a 3-day period. We identified 1 Critical, 2 High, and 3 Medium severity vulnerabilities. The most critical issue allowed unauthenticated access to customer order data via an insecure direct object reference (IDOR).

All findings include step-by-step remediation guidance. ExampleCorp has since remediated all Critical and High findings, which were retested and confirmed resolved.

Finding 1: Insecure Direct Object Reference (IDOR) — Critical

CVSS 3.1 Score: 8.6 (High)

Location: /api/orders/[ORDER_ID]

Description: The API endpoint failed to verify that the authenticated user owned the requested order ID. By incrementing the order ID, we accessed 147 customer orders belonging to other users, including names, addresses, and payment confirmation codes.

Evidence: [Screenshot redacted — shows unauthorized access to order #10492]

Remediation:

  1. Implement ownership checks on every API endpoint that returns user-specific data.
  2. Use indirect reference maps (UUIDs instead of sequential integers) for sensitive resources.
  3. Add automated tests that verify users cannot access other users' data.

Finding 2: Weak Password Policy — High

CVSS 3.1 Score: 7.5 (High)

Location: /login, /register

Description: The application allowed passwords as short as 4 characters with no complexity requirements. We successfully cracked 34% of user passwords using a basic dictionary attack in under 2 hours.

Remediation: Enforce minimum 12-character passwords with complexity requirements. Implement rate limiting and account lockout. Consider integrating Have I Been Pwned password checking.

Finding 3: Missing Content-Security-Policy Header — High

CVSS 3.1 Score: 6.5 (Medium)

Location: Global

Description: The absence of a CSP header increases the impact of any XSS vulnerability by allowing injected scripts to execute without restriction.

Remediation: Deploy a strict CSP header. Start with default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; and tighten iteratively.

Finding 4: Verbose Error Messages — Medium

CVSS 3.1 Score: 5.3 (Medium)

Description: SQL syntax errors were returned to the browser, revealing database structure and query logic.

Remediation: Implement generic error pages for users. Log detailed errors server-side only.

Finding 5: Missing Anti-CSRF Tokens — Medium

CVSS 3.1 Score: 6.1 (Medium)

Location: /contact, /profile

Description: The contact form and profile update endpoints lacked CSRF protection, allowing attackers to submit requests on behalf of authenticated users.

Remediation: Implement synchronizer token pattern or double-submit cookies for all state-changing operations.

Finding 6: SSL Certificate Chain Incomplete — Medium

CVSS 3.1 Score: 4.3 (Medium)

Description: The intermediate certificate was not served, causing trust warnings on some Android devices.

Remediation: Install the complete certificate chain on the web server.

Retest Results

On 15 August 2026, AKWEBSEC retested all Critical and High findings. All 3 issues were confirmed remediated. Medium findings were scheduled for remediation within 30 days.
