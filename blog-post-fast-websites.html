Building Fast Websites on Slow Connections

South African internet is a mixed bag. Fibre in the suburbs, LTE in the townships, and 3G when the tower is congested. Then there's load shedding, which knocks out fibre and forces users onto mobile networks that weren't designed for heavy browsing.

If your website assumes a fast, stable connection, you're losing customers before they even see your content.

Design for the Worst Case

We design every AKWEBSEC client site with a simple constraint: it must be usable on a 2Mbps connection with 200ms latency. Here's how we hit that target.

1. Aggressive Image Optimisation

Images are usually the biggest payload on any page. Our rules:

  • WebP format with JPEG fallback — typically 30-50% smaller than JPEG alone
  • Responsive images with srcset — serve smaller images to mobile devices
  • Lazy loading — images below the fold only load when the user scrolls
  • No hero images over 150KB — if it needs to be bigger, we split it or use CSS gradients

2. Minimal JavaScript

Every JavaScript file blocks rendering until it's downloaded, parsed, and executed. We:

  • Ship zero JavaScript for static content sites unless absolutely necessary
  • Use native browser features (CSS animations, Intersection Observer) instead of libraries
  • Defer or async all non-critical scripts
  • Tree-shake dependencies so we only ship code we actually use

3. Critical CSS Inlining

The styles needed to render the above-the-fold content get inlined directly into the HTML. The full stylesheet loads asynchronously afterwards. This means the first paint happens in under a second, even on slow connections.

4. Font Strategy

Custom web fonts can add 200-500KB to a page. We:

  • Use system font stacks where possible — they load instantly and look native
  • If custom fonts are required, subset them to only the characters needed
  • Use font-display: swap so text renders immediately in a fallback font

5. Caching & CDN

Static assets get cached aggressively. We set far-future expiry headers and use cache-busting filenames. For clients with international audiences, we recommend a CDN edge node in Johannesburg to cut latency.

6. Progressive Enhancement

The core content of every page must work without JavaScript. Forms submit server-side. Navigation works with plain HTML links. JavaScript is layered on top for convenience, not required for function.

The Result

Our typical client site scores 95+ on Lighthouse Performance, loads the first meaningful paint in under 1.5 seconds on 3G, and keeps total page weight under 500KB. That's the difference between a visitor who waits and one who bounces.

Fast websites aren't just a technical vanity — in South Africa, they're a business necessity.
